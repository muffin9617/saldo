# A01–A07 本地演算原型

日期：2026-11-22，香港时间。仅供用户确认产品逻辑，不推送、不部署、不执行 Supabase 迁移。

启动：`python3 prototype/server.py`，打开 http://127.0.0.1:4177/ 。直接使用虚构演算账号，无需登录。

本目录与 `dist` 分离；沿用正式版琥珀样式、Logo、返回保护和滑动规则。服务器只允许读取列明的页面／脚本／资源，不代理 API，不提供写接口。浏览器 CSP 的 connect-src 为 none；原型没有 Supabase SDK、服务端密钥或真实账号连接。不存在生产数据的迁移或覆盖。

演算状态只保存在该地址的浏览器 localStorage，独立键 `saldo.prototype.a01-a07.v1`。刷新保留；「我的 → 重置虚构数据」只重置该键，不清空其他预览或真实账号数据。损坏数据不自动覆盖，存储失败保留输入，多窗口版本冲突要求刷新。不同浏览器／设备的数据不互通。

## 本轮范围

| 编号 | 原型实现 |
| --- | --- |
| A01 | 首页／储值／订阅／我的；金额余额旧例和模糊周期旧例保留原数据，不反推历史 |
| A02 | 「＋」只新增一条独立储值或订阅记录。储值分余额储值／次数权益，记录品牌、充值／购买日期、费用和获得的权益；余额默认等于充值金额，赠送时可修改到账值。新建不提供补录模式、历史费用未知切换或当前剩余修改入口 |
| A03 | 金额型提供记录消费、更新余额、再充一笔；次数型提供记录使用、更新剩余、再买一次；直接更新剩余时备注可选，不反推历史消费 |
| A04 | 操作前后数值、支付和备注历史；最新未发生后续修改的操作可撤销；撤销留痕、付款从统计排除 |
| A05 | 精确日／周／月／年周期、人工确认续费、下一到期日建议；周期费用是否更新由用户选择；月末锚点保留；不自动推进日期或推定扣款 |

## 信息层级（2026-11-22）

- 储值：品牌是识别信息，剩余金额／次数是主信息；充值或购买费用、有效期、历史是辅助信息；列表不再显示解释性提示语。列表与详情均以剩余数值为最大字号。
- 订阅：到期日及剩余天数为主信息；费用、周期、续约方式为辅助信息。列表默认按到期排序；移除重复的费用统计栏，费用概况仅在首页呈现。
- 首页：金额余额直接呈现；次数权益分别显示实际剩余，不仅显示卡片数量，也不相加。订阅概况先展示最近到期的具体记录与日期，折合费用和预计续费居次。
- 近期安排：保留时间顺序，储值项加强剩余金额／数量，订阅费用为辅助说明。
- 新建／编辑订阅：到期日提前至名称之后，费用与周期后置；储值新建仍按充值或次数购买场景组织。
- 只调整呈现和入口层级，不自动变更余额、数量、到期日、费用或统计口径。

期限均相对首次创建虚构数据的当天生成。过一天不会自动续费或改写记录，重置数据时才重新建立演示日期。

## 统计口径

- 费用是明确记录的实付；获得 ¥220 余额不等于支付 ¥220。
- 金额使用与权益使用分开记录；使用不增加现金付款。
- 直接更新剩余是用户确认的现状，不计入购买或使用；不根据余额差额补造消费或扣次记录。备注不强制填写。
- 新增时记录本次获得的余额／权益，后续使用、更新剩余、充值、续费均从对应详情进入。直接更新剩余不补写历史消费。

## 两条独立用户链路

1. 首页／列表「＋」→ 新增储值或订阅 → 填写新条目的购买信息 → 保存为新记录。付款按用户填写的购买日期归属，不因点击「＋」自动算在今天。
2. 打开原记录 → 记录消费／使用、更新剩余、再充值／购买或续费；「编辑」修改该记录资料；「删除记录」先移入已移除记录，可恢复。修改不创建另一条卡片，也不自动追加付款。

新建时不混入「补录已有记录」或修改旧记录的模式；已有未知值、历史事件和演算数据继续保留，不自动重写。

### 储值详情布局：资料与余额维护分区

- 「卡片资料」：品牌名称、类型、有效期、直接展示的备注；详情仅保留编辑卡片；删除卡片移至编辑页底部操作栏（删除卡片／取消更改／保存更改），确认后移入已移除记录，可恢复。编辑页只维护资料，不再插入当前余额预览或操作提示。
- 「余额／权益管理」：主要字号显示当前剩余；记录消费／使用与记录充值／购买并列，前者为主要操作；手动更新剩余放在分隔线后的次级入口。过程记录与直接维护结果分开。
- 「充值／购买与使用记录」：累计付款与已记录使用量在此汇总，不插在剩余值和主要操作之间；明细直接展示，撤销只在对应历史事件内操作。
- 减少折叠与注释：备注和历史无需展开；消费、更新剩余、再充值按钮只保留动作名称，去掉重复的副说明；储值操作弹层不再重复解释统计原则。用户已填写的备注及原有历史不自动删除。
- 已移除的卡片在资料区提供恢复／永久删除；余额区只读。分区只改变界面，不清空或重算已有数据。
- 历史费用未知不当免费；原周期模糊不自动猜测。
- 实付统计以操作日期所在自然月／年为准；已移除记录仍保留付款历史，永久删除才清理关联记录。
- 预计续费只包含未来 30 天有日期、已标记自动续约且费用明确的订阅；其余记录不被推定扣款。
- 暂沿用 CNY；未增加多币种或银行／商家自动同步。

## 检查

`node tests/prototype/model.mjs` 检查费用／权益分离、组合权益、数值边界、未知与零、撤销、不可变历史、校准、周期折合、月末日期和续费。

`node tests/prototype/browser.cjs` 需要 Playwright，可通过 SALDO_PLAYWRIGHT_MODULE 指定已安装模块。覆盖完整购买／使用／充值／校准／续费／撤销、未知信息、优惠费用、刷新持久化、未保存保护、系统返回、存储失败、归档恢复及 320／390／1024px 排版。网络只允许原型本地 origin。

上线前仍需另行设计服务端数据模型、权限、迁移及端到端验收；本原型不把演算状态写入既有线上字段。确认后再整理发布代码。

详情资料的有效期与备注采用统一标签列对齐。历史采用紧凑行式布局，以入账／出账／调整图标区分动作，第一行显示事件和实付，第二行显示日期和变化；长内容、用户备注自然换行，不截断历史。

订阅详情与储值共用资料区对齐、编辑入口、紧凑历史行和底部编辑操作栏。结构为订阅资料（费用／周期／续约方式／备注）、续费管理（突出到期日、记录续费）、购买与续费记录（累计实付与明细）。续费使用循环箭头图标，首次购买使用入账图标；删除订阅收进编辑页。周期未知仍保持未知，续约标记不自动生成付款或推进日期。

详情图标遵循同一语义：入账箭头对应充值／购买，出账箭头对应消费／使用，调节图标对应手动维护，循环箭头对应续费；资料使用编辑、日历、费用、周期和备注图标，均保留文字标签。
