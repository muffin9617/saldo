# Saldo 邮件内容规范 v1.1

日期：2026-11-21。适用 M01–M14。设计已获用户确认；M14 已随 saldo-notifications v19 部署，M01–M13 仍待在 Supabase 控制台保存。真实邮件链路验收独立记录。

## 固定内容顺序

主题 → 预览文案 → 品牌 → 邮件类别 → 事件标题 → 事件说明 → 必要详情 → 行动指引／操作 → 异常处理 → 支持页脚。

- 主题固定以「Saldo · 」开头，随后说明事件；M14 追加订阅名称和剩余天数。
- 预览文案独立编写，说明下一步或是否需要操作，不复制正文首段，不放令牌或验证码。
- 正文先说明发生了什么，再展示已知事实。缺失字段不显示，不编造时间、设备、IP、邀请人或有效期。
- 固定术语：密码／邮箱／手机号「更新」，登录方式「关联／解除」，验证方式「添加／移除」。
- 操作链接紧邻触发条件或说明。异常说明已有「联系 Saldo」时，直接加 mailto 链接，不在页脚重复；其他邮件在页脚保留「需要帮助？联系 Saldo」。底部署名统一为 Saldo。
- M01–M13 附 Supabase 服务说明；只有 M14 附「管理通知偏好」，不暗示账号安全邮件由订阅提醒开关控制。

## 操作层级

| 类型 | 邮件 | 行动内容 | 权重 |
| --- | --- | --- | --- |
| 完成操作 | M01、M02、M04、M09、M10 | 验证邮箱／重置密码／确认邮箱变更／接受邀请／登录 Saldo | 金色主按钮；一封邮件一个主要操作 |
| 验证码 | M08 | 在发起操作的原页面输入验证码 | 突出验证码，不添加跳转按钮 |
| 安全事件 | M03、M05–M07、M11–M13 | 本人操作无需处理；异常时按说明行动 | 不单设「打开 Saldo」；异常说明内提供打开应用或联系支持的文字链接 |
| 到期提醒 | M14 | 核对订阅与续订安排 | 金色「查看订阅」按钮；「管理通知偏好」只在异常说明的相关语句中提供链接 |

M14 当前链接仍打开首页，直达具体订阅仍属于 G05，修改按钮措辞不代表已实现深层链接。

M01／M02 的链接失效说明中，「返回 Saldo」直接链接到正式站。M08 的原操作页面、M09 的邀请方及未开放的邮箱变更／无密码流程，没有经核验的具体地址时保留文字指引，不编造页面或将邀请方错误链接到 Saldo 支持。纯文本版本在相应说明旁附 URL／邮箱，同一入口不再单独重复列出。

## 异常处理

- M01：非本人注册可忽略；链接失效重新申请验证。
- M02：非本人请求可忽略，不会仅因收到邮件而改变密码；链接失效重新申请。
- M03：非本人修改，使用「忘记密码」重置密码并联系支持。
- M04：非本人请求不确认并联系支持；失效重新发起邮箱变更。
- M05：非本人变更邮箱，联系支持核查邮箱和访问权限；不假定原邮箱还能收取重置邮件。
- M06：非本人关联，联系支持核查登录方式，并检查相应第三方账号安全；不暗示仅改 Saldo 密码即可解除第三方身份。
- M07、M11–M13：按对应登录方式、手机号或验证方式事件联系支持核查；不统一套用重置密码。
- M08：不透露验证码；非本人可忽略；失效返回原页面重新验证。
- M09：不认识邀请方则不接受；失效联系邀请方重发。
- M10：非本人不点击；失效重新发起登录。
- M14：信息有误在应用修改订阅；不需要提醒时管理偏好；明确记录不代表扣款或续约结果。当天的 HTML 和纯文本均写「今天到期」。

未开放的产品流程仍是备用模板；文案完成不等于相关流程已开放或验收。G01–G03 的线上状态按验收清单维护。

## 维护与检查

统一场景表、HTML 与纯文本渲染位于 `supabase/functions/saldo-notifications/email-templates.js`。`emails/auth-templates.mjs` 只导出该场景表和配置补丁，避免 M01 与其他邮件单独维护。

运行 `node emails/build-auth-template.mjs` 后，所有可复制 HTML、主题和配置补丁同步更新。预览页收件箱摘要读取同一封邮件的 preheader，不另外写固定摘要。

`node tests/auth-emails.cjs` 检查主题、摘要、操作权重、异常指导、官方变量、空值、内容转义、生成物和验证回调；`node tests/notification-delivery.cjs` 检查原发送规则没有改变。浏览器检查覆盖手机、桌面、深色、超长事件信息和无图片。真实收信及 Supabase 配置验收仍需独立执行。

变量依据：https://supabase.com/docs/guides/auth/auth-email-templates
